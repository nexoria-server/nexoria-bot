==================================================
WICHTIG – ARBEITSWEISE
==================================================

Du arbeitest an einem bereits bestehenden Discord-Bot für Nexoria Craft.

Deine Aufgabe ist es, das bestehende Projekt zuerst vollständig zu analysieren und anschließend ALLE unten genannten Anforderungen professionell in das bestehende System zu integrieren.

Nimm dir so viel Zeit, wie du benötigst.

OPTIMIERE NICHT AUF SCHNELLIGKEIT.

Qualität, Stabilität, Sicherheit, Performance, saubere Architektur, Wartbarkeit, Erweiterbarkeit und eine professionelle Benutzeroberfläche haben absolute Priorität.

Lieber benötigst du deutlich länger und setzt alles sauber um, als dass du schnell eine halbfertige Lösung ablieferst.

WICHTIG:

Bevor du Änderungen machst:

1. Bestehenden Code vollständig analysieren.
2. Projektstruktur verstehen.
3. Vorhandene Systeme verstehen.
4. Datenbank verstehen.
5. Bestehende Panels verstehen.
6. Bestehende Commands verstehen.
7. Bestehende Rollen- und Berechtigungslogik verstehen.
8. Bestehende Ticket-, Bewerbungs-, Team-, Giveaway-, Minecraft- und Moderationssysteme verstehen.
9. Prüfen, was bereits vorhanden ist.
10. Bestehende funktionierende Systeme möglichst erweitern statt unnötig komplett neu zu bauen.
11. Erst danach Architektur und Umsetzung planen.

Keine Dummy-Funktionen.
Keine Fake-Daten.
Keine nur optisch funktionierenden Buttons.
Keine halbfertigen Features.
Keine unnötigen parallelen Systeme.

Eine Funktion gilt erst als fertig, wenn Backend, Datenbank, UI, Permissions, Fehlerbehandlung, Neustartverhalten und Multi-Guild-Fähigkeit funktionieren.

==================================================
1. HAUPTZIEL
==================================================

Der bestehende Discord-Bot soll zu einem professionellen, modularen und vollständig konfigurierbaren Nexoria-Craft-Management-System weiterentwickelt werden.

Das System muss möglichst auch auf anderen Discord-Servern eingesetzt werden können.

Deshalb dürfen KEINE wichtigen Einstellungen fest im Code eingebaut sein.

NICHT hardcoden:

- Server-IDs
- Rollen-IDs
- Kanal-IDs
- Kategorie-IDs
- serverabhängige Konfigurationen

Alle Einstellungen müssen pro Discord-Guild gespeichert werden.

Guild A darf niemals versehentlich Einstellungen von Guild B verwenden.

==================================================
2. ZENTRALES ADMIN-/KONFIGURATIONSPANEL
==================================================

Es soll ein professionelles zentrales Administrationssystem geben.

Hauptbereiche:

⚙️ Administration

- 👥 Team-System
- 🔐 Rollen & Berechtigungen
- 🎫 Ticket-System
- 📝 Bewerbungen

- ⚙️ Allgemeine Einstellungen

Alle wichtigen Einstellungen sollen möglichst über Panels, Buttons, Select-Menüs und Modals vorgenommen werden können.

Der Administrator soll für normale Änderungen möglichst NICHT den Code bearbeiten müssen.

==================================================
3. ZENTRALES ROLLEN- UND BERECHTIGUNGSSYSTEM
==================================================

Es muss ein großes zentrales Panel geben:

🔐 Rollen & Berechtigungen

Dieses Panel übernimmt möglichst die gesamte Rollen- und Berechtigungsverwaltung.

Der Administrator soll dort einstellen können:

- Welche Rolle für welche Teamstufe zuständig ist.
- Welche Rollen Bewerbungen bearbeiten dürfen.
- Welche Rollen Tickets bearbeiten dürfen.
- Welche Rollen Archive sehen dürfen.
- Welche Rollen Moderationsaktionen durchführen dürfen.
- Welche Rollen Minecraft-Spielerdaten sehen dürfen.
- Welche Rollen Giveaways verwalten dürfen.
- Welche Rollen Announcements senden dürfen.
- Welche Rollen @everyone/@here oder bestimmte Rollen pingen dürfen.
- Welche Rollen das Team-Leitungs-Panel sehen/bearbeiten dürfen.
- Welche Rollen das System konfigurieren dürfen.

Mehrere Rollen müssen überall dort möglich sein, wo mehrere Rollen benötigt werden.

Beispiel:

Support-Tickets:
- Supporter
- Moderator
- Moderator+
- Admin

Alle ausgewählten Rollen erhalten Zugriff.

==================================================
4. ROLLEN AUS DISCORD AUSWÄHLEN
==================================================

Rollen sollen möglichst über Discord Role-Select-Menüs ausgewählt werden.

KEINE manuelle Eingabe von Rollen-IDs als normale Konfiguration.

Der Bot soll die vorhandenen Rollen des Servers auslesen und zur Auswahl anbieten.

Wenn eine konfigurierte Rolle gelöscht wird:

- Bot darf nicht abstürzen.
- Rolle als ungültig erkennen.
- Administrator informieren.
- Neukonfiguration ermöglichen.

==================================================
6. HÖCHSTE TEAMROLLE
==================================================

Ein Spieler darf in der normalen Team-Liste nur EINMAL erscheinen.

Wenn ein Spieler mehrere Teamrollen besitzt, wird nur seine höchste konfigurierte Teamrolle angezeigt.

Beispiel:

Ein Spieler besitzt:

Owner
Admin
Developer
Supporter

Dann erscheint er ausschließlich unter:

Owner

NICHT zusätzlich unter Admin, Developer oder Supporter.

Die Prioritäten müssen über das Rollenpanel konfigurierbar sein.

- Berechtigungsstufe

8. TEAM-LISTE AUTOMATISCH AKTUALISIEREN
==================================================

Die Team-Liste soll standardmäßig alle 30 Sekunden aktualisiert werden.

Wenn sich nichts geändert hat, soll keine unnötige Discord-Nachricht bearbeitet werden.

38. GIVEAWAY-SYSTEM
==================================================

Das Giveaway-System muss geändert werden.

NICHT mehr:

Der Gewinner bekommt ein Ticket per DM.

Stattdessen:

1. Giveaway endet.
2. Gewinner wird ermittelt.
3. Gewinner wird im Giveaway-Kanal angezeigt.
4. Nur der Gewinner bzw. die Gewinner sehen die Möglichkeit, ein Ticket zu erstellen.
5. Gewinner kann einmal ein Ticket erstellen.
6. Nach Erstellung verschwindet die Möglichkeit.
7. Ticket wird direkt in die Giveaway-Gewinner-Kategorie erstellt.
8. Im Ticket steht automatisch, was gewonnen wurde.
9. Admins sehen alle wichtigen Giveaway-Informationen.

- Bewerbungsrollen müssen vollständig über ein Panel konfigurierbar sein.

- Neue Commands sollen mit Erklärungen berücksichtigt werden.

- @everyone, @here und Rollen müssen über das Berechtigungssystem geschützt werden.
